## อุปกรณ์ (ต่อวงจรไว้ให้แล้ว)

| อุปกรณ์ | การเชื่อมต่อ |
|---|---|
| ESP32-S3 | บอร์ดหลัก |
| VL53L0X (Laser ToF Sensor) | สื่อสารแบบ I2C (SDA, SCL) |

## ไลบรารีและการตั้งค่าบอร์ด

### ไลบรารีที่ใช้

| ไลบรารี | ใช้ทำอะไร | ที่มา |
|---|---|---|
| `WiFi.h` | เปิด WiFi แบบ Access Point (`WiFi.softAP()`) | มาพร้อม ESP32 Arduino Core ไม่ต้องติดตั้ง |
| `WebServer.h` | สร้าง HTTP Web Server (`server.on()`, `server.send()`) | มาพร้อม ESP32 Arduino Core ไม่ต้องติดตั้ง |
| `Wire.h` | สื่อสาร I2C กับเซนเซอร์ (`Wire.begin(SDA, SCL)`) | มาพร้อม ESP32 Arduino Core ไม่ต้องติดตั้ง |
| `Adafruit_VL53L0X.h` | อ่านค่าระยะจาก VL53L0X (`lox.begin()`, `lox.rangingTest()`) | **ติดตั้งเพิ่ม** — Library Manager ค้นหา `Adafruit_VL53L0X` (by Adafruit) |

```cpp
#include <WiFi.h>
#include <WebServer.h>
#include <Wire.h>
#include "Adafruit_VL53L0X.h"
```

> ไม่ต้องใช้ไลบรารีอื่นนอกเหนือจากนี้ หน้าเว็บและกราฟเขียนด้วย HTML + JavaScript ฝังไว้ในโค้ด (ห้ามโหลด library จาก CDN)

## โจทย์

จงเขียนโปรแกรมให้ ESP32-S3 เปิด WiFi แบบ **Access Point (AP Mode)** แล้วสร้าง **Web Server** ที่เปิดจากมือถือได้ โดยหน้าเว็บต้องแสดงค่าระยะทางจาก VL53L0X แบบ real-time มี **กราฟ (chart)** และมีปุ่มเปิด/ปิด Relay 2 ตัว

### ข้อกำหนดที่ 1 — WiFi Access Point

| ค่า | ต้องเป็น |
|---|---|
| SSID | `ESP32-S3-XXXX` โดย `XXXX` คือ **เลข 4 หลักสุดท้ายของรหัสนักศึกษา** (ไม่นับเครื่องหมาย `-`) เช่น รหัส `690000012345-6` จะได้ `ESP32-S3-3456` |
| Password | `12345678` |
| IP Address | `192.168.4.1` |

### ข้อกำหนดที่ 2 — ชื่อและรหัสนักศึกษา

หน้าเว็บต้องแสดง **ชื่อ-นามสกุล** และ **รหัสนักศึกษา** ของตนเอง

### ข้อกำหนดที่ 3 — ค่าระยะทาง

- แสดงระยะทางที่อ่านได้จาก VL53L0X เป็น **เซนติเมตร (cm)** บนหน้าเว็บ
- ค่าต้อง **อัปเดตเองอย่างน้อยทุก 1 วินาที** โดยไม่ต้องกด Refresh
- ถ้าไม่มีวัตถุ หรืออ่านค่าไม่ได้ ให้แสดงข้อความ `OUT OF RANGE`

### ข้อกำหนดที่ 4 — กราฟ (Chart)

- แสดงกราฟเส้นของค่าระยะทาง **อย่างน้อย 20 ค่าล่าสุด** และเลื่อนตามเวลาแบบ real-time
- **ต้องวาดกราฟเองด้วย `<canvas>` หรือ SVG** ห้ามโหลด library จากอินเทอร์เน็ต (เช่น Chart.js จาก CDN) เพราะมือถือที่เชื่อมต่อ AP ของ ESP32 จะไม่มีอินเทอร์เน็ต (ดูตัวอย่างการวาดกราฟได้จาก Lab 7)

### ข้อกำหนดที่ 5 — การควบคุม Relay ผ่านมือถือ

- มีปุ่ม **RELAY 1** และ **RELAY 2** กดแต่ละครั้งเพื่อสลับสถานะ เปิด ↔ ปิด
- หน้าเว็บแสดงสถานะ `ON` / `OFF` **ตรงกับสถานะจริงของ Relay** (ON = Relay ทำงาน ได้ยินเสียงคลิกและไฟบนโมดูลติด)

> **คำแนะนำ:** อย่าใช้ `delay()` ใน `loop()` ให้ใช้ `millis()` จับเวลาการอ่านเซนเซอร์แทน มิฉะนั้นหน้าเว็บจะตอบสนองช้าหรือค้าง

## เกณฑ์การให้คะแนน (20 คะแนน)

ให้คะแนนแบบ **ไล่ระดับ** ตามสิ่งที่ทำงานได้จริงบนมือถือ **ทำครบทุกอย่างได้เต็ม 20 คะแนน**

### ขั้นที่ 1 — หาระดับคะแนน

ให้เลือก **ระดับสูงสุด** ที่นักศึกษาทำได้ครบทุกเงื่อนไขในแถวนั้น

| คะแนน | ค่าระยะ | Relay | Chart | สิ่งที่ทำได้ |
|:-:|:-:|:-:|:-:|---|
| **20** | ✅ | ✅ | ✅ | **ครบทุกอย่าง** — เปิดเว็บจากมือถือได้ มีชื่อ-รหัส แสดงค่าระยะ real-time มี Chart และสั่ง Relay ผ่านมือถือได้ |
| **16** | ✅ | ✅ | ❌ | แสดงค่าระยะและสั่ง Relay ได้ แต่ **ไม่มี Chart** |
| **14** | ✅ | ❌ | ✅ | แสดงค่าระยะและ Chart ได้ แต่ **สั่ง Relay ไม่ได้** |
| **12** | ✅ หรือ ✅ | | ❌ | ทำได้ **อย่างใดอย่างหนึ่ง** — แสดงค่าระยะ **หรือ** สั่ง Relay ได้ |
| **8** | ❌ | ❌ | ❌ | **เปิดหน้าเว็บจากมือถือได้** แต่ยังไม่มีค่าระยะและสั่ง Relay ไม่ได้ |
| **5** | — | — | — | **ปล่อย WiFi AP ได้** (มือถือเชื่อมต่อได้) แต่เปิดหน้าเว็บไม่ได้ **หรือ** อ่านค่าระยะได้เฉพาะใน Serial Monitor |
| **2** | — | — | — | **Compile และ Upload ผ่าน** แต่ระบบไม่ทำงาน |
| **0** | — | — | — | Compile ไม่ผ่าน / ไม่มีงาน / ทุจริต |

**ความหมายของ ✅**
- **ค่าระยะ ✅** = หน้าเว็บแสดงค่าระยะจากเซนเซอร์จริง เปลี่ยนตามวัตถุที่เคลื่อนที่
- **Relay ✅** = กดปุ่มบนมือถือแล้ว Relay คลิกได้จริงอย่างน้อย 1 ตัว
- **Chart ✅** = มีกราฟที่วาดจากค่าระยะจริงบนหน้าเว็บ

### ขั้นที่ 2 — หักจุดบกพร่อง (ใช้กับระดับ 12 ขึ้นไปเท่านั้น)

ตรวจรายการต่อไปนี้ **พบ 1 จุด หัก 2 คะแนน** แต่คะแนนสุทธิต้อง **ไม่ต่ำกว่า 8** (เพราะยังเปิดหน้าเว็บได้)

| # | จุดบกพร่อง | วิธีตรวจ |
|:-:|---|---|
| 1 | ไม่มีชื่อ-นามสกุล หรือไม่มีรหัสนักศึกษาบนหน้าเว็บ (ขาดอย่างใดอย่างหนึ่ง) หรือ SSID ไม่ตรงรูปแบบ `ESP32-S3-XXXX` | ดูหน้าเว็บ / รายชื่อ WiFi บนมือถือ |
| 2 | ค่าระยะต้องกด Refresh ถึงจะเปลี่ยน หรือคลาดจากไม้บรรทัดเกิน ±2 cm หรือไม่แสดง `OUT OF RANGE` เมื่อไม่มีวัตถุ | วางกระดาษที่ 10 cm และ 30 cm แล้วเอาออก |
| 3 | Relay สั่งได้ **ตัวเดียว** หรือสถานะ `ON`/`OFF` บนเว็บไม่ตรงกับ Relay จริง | กดปุ่มทั้ง 2 ตัว ดูไฟบนโมดูล |
| 4 | Chart ไม่ขยับเอง หรือมีน้อยกว่า 20 ค่า | ขยับกระดาษเข้า-ออก ดูกราฟ |

> ตรวจเฉพาะจุดบกพร่องของสิ่งที่นักศึกษาทำได้ เช่น ระดับ 16 (ไม่มี Chart) ไม่ต้องตรวจข้อ 4 อีก เพราะไม่ได้คะแนนส่วน Chart อยู่แล้ว

### ตัวอย่างการคิดคะแนน

| สิ่งที่นักศึกษาทำได้ | ระดับ | หัก | สุทธิ |
|---|:-:|:-:|:-:|
| ครบทุกอย่าง ไม่มีจุดบกพร่อง | 20 | 0 | **20** |
| ครบทุกอย่าง แต่ลืมใส่รหัสนักศึกษา | 20 | −2 | **18** |
| ครบทุกอย่าง แต่ Relay 2 ไม่ทำงาน และ Chart ไม่ขยับ | 20 | −4 | **16** |
| ไม่มี Chart, ค่าระยะและ Relay ทั้ง 2 ตัวทำงานถูกต้อง | 16 | 0 | **16** |
| ไม่มี Chart, สถานะปุ่มกลับด้าน (เว็บ `OFF` แต่ Relay ทำงาน) | 16 | −2 | **14** |
| สั่ง Relay ได้อย่างเดียว ยังไม่มีค่าระยะ | 12 | 0 | **12** |
| แสดงค่าระยะได้อย่างเดียว แต่ต้องกด Refresh และไม่มีชื่อ | 12 | −4 | **8** |
| ปล่อย WiFi ได้ แต่เปิด `192.168.4.1` ไม่ขึ้น | 5 | — | **5** |

## กติกาการตรวจ

| เรื่อง | กติกา |
|---|---|
| **การขอตรวจ** | ขอตรวจได้ **ไม่เกิน 2 ครั้ง** ใช้คะแนนครั้งที่ **สูงกว่า** (ตรวจครั้งแรกแล้วกลับไปแก้ต่อได้) |
| **อุปกรณ์เสีย** | ถ้าผู้คุมสอบยืนยันว่าอุปกรณ์เสีย จะเปลี่ยนชุดให้และ **ชดเชยเวลา** เท่ากับเวลาที่เสียไป ไม่หักคะแนน |
| **หมดเวลา** | ผู้ที่ยกมือขอตรวจก่อนหมดเวลาจะได้ตรวจตามคิว แต่ห้ามแก้โค้ดเพิ่มระหว่างรอ ถ้ายังไม่เคยขอตรวจเลย ผู้คุมสอบจะตรวจสภาพที่บอร์ดเป็นอยู่ ณ เวลาหมดเวลา |
| **ทุจริต** | ใช้ AI คัดลอกโค้ด หรือให้ผู้อื่นทำแทน ได้ **0 คะแนน** ผู้คุมสอบสุ่มถามอธิบายโค้ดได้ 1–2 คำถาม ถ้าอธิบายโค้ดของตนเองไม่ได้ จะส่งอาจารย์ผู้สอนพิจารณา |
